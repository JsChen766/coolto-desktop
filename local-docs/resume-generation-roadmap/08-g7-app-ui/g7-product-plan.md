# G7 App 前端产品与实施计划

> 状态：产品决策已固化；首轮实现完成并通过质检  
> 更新日期：2026-07-24  
> 前置状态：G1–G6 已完成并通过阶段质检

## 1. 本阶段目标

把 G1–G6 已完成的简历生成、真实 Chromium 测量、保存审批、跨端互通和 PDF 导出能力，
整合为桌面 App 内可持续编辑、可与 Agent 协作、可确认修改、自动本地保存、可从历史聊天
恢复并可回退本地版本的简历工作区。

G7 不重做生成算法、云端存储格式或模板；Canvas、Agent、保存和导出必须继续使用同一份
`structured` 与同一份模板实现。

## 2. 已确认的质量目标

以下是默认优秀目标，不替代现有硬门槛：

| 指标 | 默认优秀目标 | 现有保存硬门槛 |
| --- | ---: | ---: |
| 页面占比 | 目标 92% | 至少 85% |
| 最低 bullet 尾行 | 至少 75% | 至少 66.71% |

约束：

- Agent 在素材允许时主动向 92% / 75% 优化；
- 达到现有硬门槛但未达到优秀目标时，仍可保存和导出，不制造无事实依据的填充内容；
- 页面仍必须严格一页，字体和事实硬门槛保持不变；
- G7 高级详情展示真实测量值及其状态，不由模型估算。

## 3. 已确认的信息架构

### 3.1 双栏工作区

- 左侧是现有 Agent 对话区；
- 右侧是可展开/收起的 A4 简历 Canvas；
- Canvas 是持续存在的工作区，不是聊天消息中的一次性图片或附件；
- Canvas 展开后仍保留聊天区，用户可以一边看简历一边继续对话。

### 3.2 顶部工具入口

Canvas 未展开时不显示其专属操作。Canvas 展开后，在现有展开/收起按钮左侧，同一行显示：

1. 高级详情；
2. 保存到云端；
3. 导出。

上述入口使用项目现有的 `@lucide/vue` 图标库与 `IconButton` 交互规范，不引入另一套图标。
实现顺序为高级详情、保存到云端、导出、预览/收起；全部使用 Lucide 图标与现有
`IconButton`。未完成事实复核、存在待接受 AI 修改或未通过保存门禁时，保存与导出保持禁用。

### 3.3 高级详情

页面顶部不常驻质量指标。高级详情中只展示以下四项，不增加其他技术诊断：

1. 页面占比；
2. 最低尾行；
3. 事实完整性；
4. JD 覆盖。

高级详情采用无边框填充式 popover；数值展示一位小数。事实状态为“已通过 / 待重新验证 /
未通过”，没有 JD 时显示“未关联 JD”。

## 4. 已确认的编辑与 Agent 协作

### 4.1 直接编辑

- 右侧简历可像文档编辑器一样直接修改文字；
- 直接编辑后的 Canvas 必须重新走结构校验、真实排版测量和质量状态更新；
- 展示层不能维护一份脱离 `structured` 的自由 HTML 文档。
- Canvas 是产品概念，技术上使用与预览、测量和 PDF 相同模板的 A4 DOM 文档，不使用
  位图式 HTML Canvas；
- DOM 页面固定为 A4 比例和排版尺寸。受显示器缩放影响，屏幕上的物理厘米数不保证等于
  真实纸张，但换行、间距、页面占比和 PDF 输出保持一致；
- bullet、技能等生成型叙述内容允许直接编辑；
- 固定 section 标题、教育信息、公司、职位、日期和联系方式等固定资产字段默认只读，
  避免简历展示与个人资料、经历库及 Web 端固定资产互相矛盾；
- 固定字段在 hover/focus 时显示锁定状态；用户尝试编辑时弹出贴近字段的说明，解释来源和
  禁止直接修改的原因，并提供“在聊天中修改”入口；
- 编辑边框、拖拽手柄、锁定提示和差异高亮必须作为页面外层交互覆盖物，不得改变简历本身
  的排版尺寸或进入 PDF。

### 4.2 拖入聊天进行修改

- 用户可将单个 bullet 拖入聊天区；
- 用户可将一整段经历拖入聊天区；
- 拖入对象必须保留稳定 ID 和结构化引用，不能只复制一段失去来源关系的纯文本；
- Agent 修改时仍需获得完整简历前文、证据账本、页面预算和当前 JD 上下文，避免重复或局部最优。

bullet 和经历左侧使用 Lucide `GripVertical` 明确显示拖拽手柄；Composer 接收结构化引用后
显示填充式引用条，并自动填入“请帮我修改这部分内容”。引用保留 artifact、目标类型和稳定
目标 ID。点击手柄提供与拖拽等价的键盘/精确指针降级路径，Composer 在拖入时显示松手提示。

### 4.3 AI 修改的接受/拒绝

- Agent 完成局部修改后，Canvas 展示修改后的待确认版本；
- 预览下方显示“接受”和“拒绝”按钮，交互参考代码编辑 Agent 的变更确认；
- 接受后，本次修改进入当前工作版本；
- 拒绝后，撤销且只撤销本次 AI 修改，恢复到发起修改前的版本；
- 接受只更新本地工作稿，不自动更新云端简历当前内容；
- 接受/拒绝栏固定在 Canvas 面板底部，不属于 A4 页面内容；
- 不设置独立“继续优化版面”操作；需要继续优化时，用户在聊天中继续提出要求。

待确认期间暂停直接编辑，防止基线漂移；首版按一次 Agent 变更整体接受或整体拒绝。变更 bullet
按文字行显示低透明度绿色荧光笔，高亮不参与测量。

## 5. 已确认的本地保存与恢复模型

### 5.1 自动本地保存

- 新生成、手动编辑和已接受的 AI 修改必须自动保存到本机；
- 自动保存不需要用户审批，也不更新云端 Resume 当前内容；
- 工作稿按登录用户和对话隔离，使用系统安全存储加密，并采用临时文件加原子替换，避免崩溃
  或断电留下半份 JSON；
- 输入过程中采用 900ms 短延迟合并保存，失焦时提交为本地检查点；
- 当前工作稿与待接受/拒绝的 AI 修改分开保存，意外退出后可以恢复到退出前的决策状态；
- 页面测量值可以重算；本地恢复至少保存 `structured`、证据引用、来源版本哈希、模板信息、
  工作稿版本和待决策修改；
- 恢复后重新读取来源版本并校验哈希。来源已变化或当前离线时仍可预览本地内容，但在完成
  重新校验前不得把状态误报为事实已通过或保存到云端。

### 5.2 聊天中的简历入口

- 每次首次生成一份简历时，在对应聊天位置插入一个持久化的本地简历 Artifact 卡片；
- 卡片可包含小型 A4 外观、简历名称、本地/云端状态、更新时间和“打开”入口；
- 卡片不复制整份简历到聊天文本，而是保存 `local_artifact_id` 和不可变本地检查点引用；
- 打开历史聊天并点击卡片，可恢复对应的本地简历检查点到右侧 Canvas；
- 若本地文件被主动删除或设备已更换，卡片明确显示“本机草稿不可用”，不能伪装为仍可恢复；
- 普通 Markdown 外链不能直接读取任意本地路径；卡片通过受控内部 IPC 解析，避免任意文件访问。

纯 href 文本可以作为无缩略图降级形式，但默认产品形态采用可辨认状态的简历 Artifact 卡片。

### 5.3 本地版本回退

- App 提供的是本地工作稿检查点历史；产品不提供云端版本列表或回退；
- 首次生成、接受 AI 修改、成组手动编辑和执行回退等有意义动作形成不可变本地检查点；
- 每次击键只更新自动保存工作稿，不创建一个历史版本，避免版本列表失控；
- 恢复某个历史检查点时，将其复制为新的本地工作头，不删除它之后的检查点，因此仍可再次
  切回；
- 本地预览、回退和恢复不调用云端写接口；只有用户点击“保存到云端”或“更新云端简历”
  并通过 G5 审批后，才创建新云端 Resume 或更新已关联 Resume 的当前内容；
- 本地版本入口位于 Canvas 标题栏；首版显示动作名称、修订号和时间，点击后把对应检查点恢复
  为新的本地工作头，不实现逐字 diff 对比。

### 5.4 与现有聊天持久化的关系

当前聊天存储会主动移除 `prepare_resume_candidate`、`patch_resume_candidate` 等临时候选结果，
因此不能把聊天消息当作草稿数据库。G7 新增独立的 `ResumeDraftStore`，聊天只持久化受控引用：

```text
聊天 Artifact 卡片 ──local_artifact_id──> 加密的 ResumeDraftStore
                                          ├─ 当前自动保存工作稿
                                          ├─ 待决策 AI 修改
                                          └─ 不可变本地检查点
```

`ResumeDraftStore` 与现有 `ConversationStore`、云端保存执行器分离，避免在一个存储类中混合
聊天、草稿、版本和云端发布职责。

## 6. 已确认的本地/云端用户教育

界面必须持续说明数据所在位置，不能只依赖首次教程：

- Canvas 显示“已自动保存到本地”“正在保存到本地”或“本地保存失败”等即时状态；
- 顶部操作明确命名为“保存到云端”，不用含糊的“保存”；
- 聊天 Artifact 卡片显示“仅本机草稿”“已同步云端”或“有未同步本地修改”；
- 云端保存审批明确提示：将创建新云端简历或更新现有简历的当前内容，保存后 Web 端也可访问；
- PDF 导出说明为“导出到本地文件”，不与本地草稿或云端当前内容混为一谈；
- 首次进入可编辑 Canvas 时提供一次简短引导，后续依靠状态标签、tooltip 和操作反馈持续教育；
- 退出登录不删除本地草稿，并按用户隔离；删除聊天或本地草稿时必须说明会影响哪些恢复入口。

删除聊天时保留其关联的本地简历草稿。聊天 Artifact 卡片只是恢复入口之一，后续左侧栏将
增加独立的本地简历入口，确保删除聊天后草稿仍可被发现和打开。只有用户明确执行“删除本地
简历”时才删除草稿，并需要单独确认。

## 7. 已确认的视觉样式约束

### 7.1 复用现有主题

- G7 所有组件优先复用现有 Vue 组件、CSS 变量、间距、圆角、按钮、tooltip、深浅色主题和
  `@lucide/vue` 图标；
- 不另建一套简历工作区主题，不引入与现有 App 不一致的颜色、阴影或控件风格；
- 新组件需要同时支持现有浅色和深色主题；A4 纸张本身保持真实白纸效果，外围工作区跟随主题。

### 7.2 卡片和区域的单一容器表达

任何用于分组的卡片、面板、区域或状态块，只允许选择一种容器表达：

1. 使用背景填充，不再绘制边框；或
2. 使用边框，背景保持透明。

禁止同一个卡片同时拥有可见背景色和可见边框。hover、选中、错误和禁用状态也必须遵守该
规则，不能在已有背景填充上临时叠加边框。A4 纸张不是信息卡片，可使用现有纸张阴影表达层级。

### 7.3 修改内容高亮

- 简历中的 AI 修改采用低不透明度绿色的“荧光笔划过文字”效果；
- 高亮贴合文字行，不包围整个 block，不使用矩形边框或描边；
- 高亮不能改变文字宽度、行高、换行和排版测量；
- 深色工作区中 A4 纸张仍为白色，因此高亮以纸张上的可读性为准；
- 接受或拒绝后移除本次修改高亮。

## 8. 已确认的不做事项

- 不在预览顶部常驻页面占比、最低尾行、事实完整性或 JD 覆盖；
- 不在高级详情中加入上述四项之外的技术指标；
- 不提供“继续优化版面”按钮；
- 不为 Canvas 另建与后端不兼容的简历存储格式；
- 不允许视觉编辑绕过字体、事实、一页和尾行质量门。
- 不把“接受 AI 修改”等同于“保存到云端”；
- 不建立用户可见的云端版本列表、版本回退或 diff；
- 不依赖聊天纯文本保存完整简历草稿；
- 不让本地 Artifact 链接直接访问任意文件路径。
- 不让同一卡片或区域同时使用可见背景填充和可见边框；
- 不使用边框式、矩形框式的简历修改高亮；
- 不为 G7 建立脱离现有 App 的第二套主题或视觉语言。

## 9. 已落地的首版产品取舍

1. 手动输入在停顿 900ms 后自动写入加密本地工作稿，失焦形成有意义的本地版本；
2. AI 修改以整次提案为接受/拒绝粒度，待确认时禁止并发手动编辑；
3. Artifact 使用填充式卡片，展示名称和本地/云端状态；历史聊天和左侧“本地简历”均可打开；
4. 同一聊天的多份简历按独立 Artifact 展示，草稿生命周期不依赖聊天是否仍存在；
5. Canvas 使用 `min(720px, 56vw)` 的桌面宽度并缩放整张 A4；窄窗口优先收起预览；
6. 保存到云端与导出继续通过现有 Action Approval，不在 Canvas 内复制另一套执行逻辑；
7. `App.vue` 只做页面组合；聊天会话、草稿状态、持久化、编辑、提案与 A4 DOM 分模块实现。

实现和质检记录见 [G7 实施结果](./g7-implementation-result.md)。
