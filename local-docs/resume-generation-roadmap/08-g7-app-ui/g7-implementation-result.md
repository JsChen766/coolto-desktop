# G7 App 前端实施结果

> 状态：首轮实现完成并通过质检  
> 日期：2026-07-24

## 1. 已交付链路

- 独立于聊天记录的加密本地 `ResumeDraftStore`，按登录用户隔离并使用原子替换写入；
- 删除聊天只删除聊天文件，不级联删除关联简历草稿；左侧“本地简历”仍可打开草稿；
- 生成工具完成后把 `ResumeWorkspace` 自动同步为本地草稿，并在聊天中保存受控 Artifact 引用；
- A4 Canvas 复用 Web/隐藏测量/PDF 的同一 `renderResume`、模板 CSS 和字体资产；
- bullet 与技能叙述可直接编辑，停顿 900ms 自动保存，失焦创建本地版本；
- 固定资产默认只读，尝试编辑时解释来源限制，并提供“在聊天中修改”；
- bullet 和经历左侧提供明确的 Grip 手柄，可携带稳定 ID 拖入 Composer；点击手柄也可直接
  引用，Composer 在拖入时显示落点反馈；
- Agent 定向修改以 `base + proposed` 持久化，异常退出也保留待接受/拒绝状态；
- AI 修改按文字行使用低透明度绿色荧光笔；接受写入本地检查点，拒绝恢复基线；
- 顶部同一行提供高级详情、保存到云端、导出和预览/收起；高级详情只有四项指标；
- 本地版本列表可恢复历史检查点，恢复不产生云端写入；
- `App.vue` 从 501 行降至 267 行，对话会话、草稿状态、编辑器和存储分别拆分。

## 2. 视觉实现

  固定资产锁定说明。

## 4. 安全与一致性

- Renderer 只拿到受控结构、质量状态和稳定 ID，不拿本地草稿路径；
- 本地草稿保存完整 Workspace 但由 Electron `safeStorage` 加密；
- 手动改写会清除旧质量结论，事实未重新通过时保存到云端和导出均禁用；
- 云端保存和 PDF 导出继续走 G5/G6 的 Action Approval 与服务端/文件后检；
- App 没有创建第二套 `structured` 格式或第二套简历模板。

## 5. 截图反馈复检

2026-07-24 根据实际 App 截图复检：

- 简历 DOM 的中文字体声明为打包的 `SimSun`，英文/数字为打包的 `Times New Roman`；真实
  Electron PDF 后检也确认两种字体均已嵌入。截图中 App 标题栏仍使用产品 UI 字体，这是有意
  区分，A4 纸张内部不继承 UI 字体；
- 原实现只把很小的 bullet 圆点和经历标题设为拖拽源，缺少可发现的操作手柄与落点反馈，虽有
  底层数据传递但用户难以使用；
- 已改为明确的左侧 Grip 手柄、Canvas 操作说明、Composer 拖入反馈，并增加点击手柄的等价
  引用路径；浏览器实测 bullet 与整段经历均能在 Composer 中形成结构化简历引用。
