# P0 页面与交互设计规范

> 状态：已固化为本路线 UI 基线  
> 来源：现有 App、G7 产品决策与用户补充规则

## 1. 总原则

所有新页面必须看起来属于当前 Coolto，而不是嵌入另一套后台系统：

- 复用现有 `tokens.css`、`base.css`、字体、间距、圆角、按钮、popover 和深浅主题；
- 图标只使用当前 `@lucide/vue`，不引入第二套图标库；
- 优先扩展现有 Sidebar、Composer、Artifact 卡片、ApprovalCard 和右侧 ArtifactPanel；
- A4 简历仍使用独立纸张视觉和模板字体，产品 UI 不冒充简历字体；
- 桌面宽屏保持“聊天 + 右侧产物”双栏，窄窗口优先收起右侧区域，不挤压内容制造假布局。

## 2. 卡片与区域

任何卡片、面板、状态区、列表行分组只能选择一种容器表达：

1. 有背景填充，不绘制可见边框；或
2. 有边框，背景保持透明。

禁止背景色和边框同时存在。hover、选中、错误、拖入和禁用状态也遵守该规则。状态优先使用
文字、图标、圆点和背景明度变化，不临时叠加一圈边框。

## 3. 信息架构

### 3.1 左侧栏

保留现有顺序和密度，并逐步扩展为：

```text
新对话
简历仓库（入口）
本地简历（最近项目）
对话历史
账户与设置
```

云端简历不全部堆在侧栏。侧栏只显示仓库入口和最近本地草稿；完整筛选、分页和批量浏览进入
主工作区的“简历仓库”。

### 3.2 聊天消息

- Agent 结论仍以聊天为主，不把用户强制送进独立向导；
- 附件、JD、匹配报告和简历使用受控 Artifact 卡片，而不是普通 Markdown 本地链接；
- 卡片展示名称、来源、本地/云端状态、更新时间和一个主要操作；
- 上传、入库、删除等操作继续使用现有 ApprovalCard 的接受/拒绝/自定义路径。

### 3.3 右侧 Artifact 区

现有简历 Canvas 所在区域扩展为通用产物工作区，一次只激活一个产物：

- 简历：A4 编辑 Canvas；
- JD：原文与结构化 requirements 查看；
- 匹配报告：总分、四维拆解、亮点、缺口和建议；
- 附件：安全预览和本地解析状态。

切换产物不丢失聊天或本地草稿。顶部操作与当前产物相关，不显示无效按钮。

## 4. 各链路页面规范

### 4.1 附件

- Composer 回形针启用后打开系统文件选择器；首版沿用现有能力一次选择一份简历文件；
- 选择后在 Composer 上方使用填充式附件条，显示类型图标、名称、大小、移除和解析状态；
- 原始文件明确标记“仅本机”；经历候选接受后显示“经历已保存到云端”；
- 文档解析预览与原文件元数据分开；本路线不加入图片或通用材料关联 UI。

### 4.2 JD 入库

- 用户可直接在 Composer 粘贴 JD，不要求先进入表单；
- Agent 提取后显示填充式 JD 预览卡：岗位、公司、原文长度和 requirements 数量；P0 不展示重复状态；
- 完整原文与 requirements 在右侧 Artifact 区查看；
- “保存到云端”必须通过 ApprovalCard，未批准前持续标记“本地提案”；
- 保存后卡片变为稳定 JD 引用，可用于匹配和简历生成。

### 4.3 匹配报告

- 聊天卡片首屏只显示总分、等级、前三个亮点、最高优先级缺口和“查看完整报告”；
- 右侧完整报告显示固定四维：技能 40%、经验 35%、教育 15%、综合印象 10%；
- 每个亮点必须能展开查看对应 JD requirement 和经历来源；
- 缺口明确区分“必须”和“加分”，禁止用绿色成功态包装真实缺口；
- 无足够事实时显示“证据不足”，不显示伪精确结论；
- 报告来源过期时在标题区用填充式提示，不用边框警告框。

### 4.4 简历仓库

- 主区使用列表/表格式信息密度，不把每份简历渲染成巨大卡片；
- 行内显示名称、目标岗位/JD、云端状态、云端更新时间和本地修改状态；
- 主要操作为打开，次要操作收进现有样式的 overflow menu；
- 本地草稿与云端简历分别标识，但已建立 cloudLink 时合并为一条逻辑记录；
- P0 只提供“删除本地草稿”和云端“归档/恢复归档”；云端 Resume 删除入口隐藏或明确标注未接入；
- “是否已投递”只读取投递记录。投递模块未实现时隐藏该列或显示“投递功能尚未接入”，不得
  允许用户在简历上手动制造另一套状态。

### 4.5 本地检查点与同步冲突

- 本地历史只展示动作名称、本地修订号和时间，不提供逐字或结构化 diff；
- “恢复”将选中检查点复制为新的本地工作头，不删除之后的检查点，也不写云端；
- 仓库不展示云端 variant 列表、版本号、父版本、发布状态或云端回退入口；
- 仅本地改变时显示“有未同步本地修改”；仅云端改变时提示重新读取；两边都改变时显示明确冲突状态；
- 冲突操作只提供重读云端、另存为新简历和明确确认覆盖，不伪装成云端版本合并。

## 5. 本地与云端教育

界面必须持续显示数据位置：

- 本地文件、本地 Proposal、本地匹配报告和本地 ResumeDraft：使用“仅本机”或“本地草稿”；
- 已确认的经历、JD 和 Resume 当前内容：使用“已保存到云端”；
- 正在上传、保存失败、有未同步修改：显示明确进行中或失败状态；
- “保存”按钮必须具体写成“保存到云端”“自动保存到本地”或“导出到本地文件”；
- 退出、删除和切换账号时，说明会影响本地还是云端数据。

## 6. 可访问性与交互状态

- 所有图标按钮具有 `aria-label` 和 tooltip；
- hover 才出现的操作必须保留 focus-visible 和键盘路径；
- 拖拽必须有点击/选择降级方案；
- 异步步骤显示当前动作，支持安全取消；
- 空状态给出一个明确下一步，不堆叠多个同权按钮；
- 深浅主题、200% 缩放、940px 最小窗口和键盘导航纳入阶段验收。

## 7. 禁止事项

- 不引入新的全局主题、图标库或随意硬编码品牌色；
- 不用边框包围 AI 修改；
- 不增加云端版本、版本 diff 或本地历史 diff 界面；
- 不在 Renderer 暴露本地绝对路径；
- 不把普通聊天文本伪装成已保存固定资产；
- 不用纯颜色作为唯一状态信息；
- 不因为右侧面板出现而改变 A4 实际换行和测量尺寸。
