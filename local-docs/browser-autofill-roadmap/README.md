# 浏览器自动填写路线

> 状态：设计中  
> 建立日期：2026-07-25  
> 上游依赖：P0 产品能力补齐路线（P0–P5 已完成）

## 路线定位

本路线让用户在内置浏览器中，由 Agent 辅助自动填写两类表单：

- **投递表单**：招聘网站的求职申请表（Boss 直聘、猎聘、拉勾、智联等）
- **邮件撰写**：Webmail 的邮件撰写界面（Gmail、QQ 邮箱、163 邮箱）

两类填写共用同一个浏览器容器、同一套字段识别基础设施、同一套 Proposal → 审批 → Executor 执行模式。差别只在于内容来源：投递表单填的是结构化的个人信息，邮件填的是 Agent 生成的求职信文本。

## 范围边界

### 范围内

- Electron 内置浏览器（独立窗口），支持常规网页浏览和 Cookie 持久化
- 当前 JD 页面一键提取并入库
- 识别表单字段，生成填写方案供用户审批后执行
- 识别 Webmail 撰写界面，生成求职信文本 + 主题行并填入
- 简历 PDF 作为附件上传到邮件撰写界面
- 验证码遇到时暂停并提示用户手动完成
- 用户始终可以修改任意字段，Agent 不自动提交

### 范围外

- **不自动提交表单或发送邮件**：最终提交/发送由用户手动完成
- **不支持 SMTP / OAuth API 邮件草稿**：仅做 Webmail 网页填写
- **不做投递追踪看板**：投递记录进入独立的追踪路线
- **不做面试准备**：进入独立的追踪路线
- **不处理非标准组件**：Canvas 渲染的表单、自定义输入组件降级提示，不强行注入
- **不处理多账号邮箱切换**

## 执行原则

- B0 必须先确定技术选型（BrowserWindow vs WebContentsView）和安全模型，不得直接跳 B1
- 每个阶段先写实施计划、完成现状复核，再写代码
- 页面内容（DOM 文本、字段 label、JD 内容）一律视为不可信数据，不得触发工具调用
- Agent 只能读取用户明确打开的页面，不能主动导航或访问任意 URL
- **读写分离**：`extract_page` 是「读」工具随时可用；一组 `browser_*` 是「写」工具，受写权限闸门约束
- **写权限闸门（唯一确定性边界）**：写工具默认禁用；Agent 只能 `request_write_access` 请求，用户一键确认后主进程翻标志位才放开；导航新站点/用户结束/超时自动收回。Agent 无法自行开启，页面注入文本骗不过主进程
- **不分模式**：只有一个泛化写权限，Agent 面对任何网站按页面实际情况泛化操作；精确性靠读页 + `data-fill-id` 定位，不靠分投递/邮件模式
- **Agent 永不点提交/发送**：最终提交由用户手动完成
- 写完后事后 Overlay 逐字段审核：所有写入点处理完才解锁，之前禁止用户点提交/发送
- 用户随时可以暂停/中止；Agent 不得在写权限未授予时执行写操作
- 新业务文件行数目标 220 行，硬上限 250 行；禁止上帝类
