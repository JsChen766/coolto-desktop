# Coolto 开源桌面端 PRD（从商业全套 PRD 裁剪）

> 裁剪日期：2026-10-17  
> 源文件：用户提供的《Coolto 产品能力缺口闭环 PRD》（12 章全套）  
> 代码仓：`coolto-desktop-local`（`coolto-local-agent`，Electron + Vue + 本地 TypeScript Agent 内核）  
> **产品边界（硬约束）**：本地优先；**不连接 Coolto 云、不登录、不消耗 Credit**；模型走用户自备 OpenAI 兼容接口（Base URL + API Key + 模型名）。业务事实读本机 projection；写入走 Proposal + 宿主审批 + LocalSyncStore / Outbox，**不 Push/Pull 云端**。

## 0. 裁剪原则

### 保留
- 本地桌面 Agent 工作台能力：对话、经历、JD/匹配、简历生成与导出、投递追踪、材料库、Agent 任务与内置浏览器。
- 「可审计、控制权可见、Proposal/审批、事实可追溯」等与本地架构一致的闭环要求。
- 可在本机完成的隐私能力：本机数据导出、清除本机数据、隐私同意（本机版本记录）。

### 明确排除（开源版不做 / 不验收）
- Coolto 云账号、登录、同步、Credit/计费。
- 依赖云端的埋点经营报表、跨账号分析后台（§3 经营侧）。
- 「删除账号及云端数据」、云端恢复与云端合规删除流程（§4 中云端部分）。
- 正式商业签名/公证作为开源必达项可降级为「文档化可选」；官网 feed 与商业发布管线不纳入本 PRD 必达。
- 邮箱发送、Calendar 云写入等若代码中仍残留，按「可选/未完成」标记，**不得写进开源必达主路径**，除非本仓 README 已宣称支持且可纯本机完成。

### 验收总原则
- 一条需求只有在「无云、仅本机 + 用户自备 API」条件下可复现，才算开源 PRD 验收项。
- 桌面自测：主路径点通即可，附截图/短录屏或命令日志；不要求完整自动化 UI 框架。
- 完成定义对齐团队共识四条门槛：（1）本 PRD 主路径自测全绿；（2）README + 贡献指南 + License；（3）≥3 个 beginner-friendly issue；（4）安全审核约定写入 CONTRIBUTING。

## 1. 真实投递闭环（P0，开源裁剪版）

**目标**：在用户授权范围内，用内置浏览器完成「选简历 →（可选）找/导入岗 → 填表 → 用户确认提交 → 本机 Application/回执」；**不宣称**全网 ATS 稳定生产投递。

### 1.1 开源范围场景
1. 用户已有本机简历与经历，粘贴 JD 或打开已支持的公开申请页，由 Agent 观察页面、准备字段写入 Proposal，经用户审核后填写。
2. 遇到登录 / OTP / CAPTCHA / 法律声明：任务进入明确「等待用户」；用户接管后**恢复同一任务**，不另起炉灶。
3. 正式提交必须走专门提交动作 + 最终确认；结果明确则生成本机回执/Application；结果不明则「待核实」、**禁止自动再点提交**。

### 1.2 开源版希望闭环
1. 任务绑定冻结的本机简历版本；简历变更则暂停并要求重确认。
2. 每个写入字段可审核；敏感字段与无法确认项默认交用户。
3. 提交成功/失败/待核实在本机 Tracker 可查；本地写入失败不得导致重复提交招聘站。
4. 产品内维护「正式支持 / 实验性 / 不支持」站点说明；未列入稳定清单的不得写成已稳定。

### 1.3 验收（开源）
- [ ] 文档列出当前正式支持与实验性站点/来源边界。
- [ ] 本机走通至少一条：选定简历 → 打开申请页 → 多步骤填表 → 上传简历 → 字段审核 → 提交确认 → 本机 Application/回执。
- [ ] 任务全程简历版本一致；变更可阻止提交。
- [ ] 登录/OTP/CAPTCHA/接管可暂停并恢复同一任务。
- [ ] 用户拒绝最终提交时，网站未提交，本机无 Application。
- [ ] 成功时仅一条回执+一条 Application；结果不明或崩溃恢复后不自动重复提交。
- [ ] 失败有可读原因与下一步，无「无提示卡住」。

## 2. 简历生成质量与稳定性（P0）

**目标**：本机 Agent 生成可交付一页简历（通用 / 针对 JD / user_directed），事实可追溯，预览=保存=PDF 同源。

### 2.1 场景（开源保留）
- 针对 JD 生成；通用简历（不绑虚构 JD）；素材不足或用户指定经历；连续生成与本机历史草稿复用。

### 2.2 希望闭环
1. 路径选择正确并说明当前目标。
2. 内容来自本机 Experience / 本轮用户补充 / 经核验的历史草稿；禁止为关键词编造。
3. 数字与因果可回源；素材不足时最多追问关键缺口，用户说「没有更多」后停止同问并交付现有事实允许的最好版本（可标未达标）。
4. user_directed 不掺入未指定经历；缺口作警告。
5. 终态明确：可交付 / 等补充 / 未达标草稿 / 取消 / 失败。
6. 预览、本机保存、PDF 导出同一修订。

### 2.3 验收（开源）
- [ ] 针对性、通用、历史复用、user_directed 各至少 1 条本机完整样本。
- [ ] 自自然语言请求起，合理时间内进入明确终态（以本机可复现为准；原 600s 云约束改为「可配置超时 + 有终态」）。
- [ ] 达标样本真实单页；占用/溢出/尾行过正式门槛。
- [ ] 事实可追溯；「没有更多材料」后不重复追问。
- [ ] 通用简历不绑虚构 JD、不伪造岗位覆盖率。
- [ ] user_directed 不加入未指定经历。
- [ ] 历史复用不改坏原草稿；新 JD 下事实与版面重验。
- [ ] 预览 / 本机保存 / PDF 一致。

## 3. 本机可观测性（P0 裁剪自「埋点」）

**开源不做**：云端经营后台、跨用户漏斗报表。

**开源要做**：开发者与贡献者可在本机诊断主链路。

### 3.1 希望闭环
1. 核心动作（启动、导入经历、导入 JD、匹配、生成简历、导出、投递任务阶段）有本机可查日志或 debug 面板。
2. 区分开始/成功/失败/取消/等待用户。
3. **最小数据原则**：日志默认不含简历正文、经历正文、API Key、密码、验证码、绝对隐私路径明文。

### 3.2 验收
- [ ] CONTRIBUTING / docs 说明如何打开本机诊断。
- [ ] 能从一次本机操作重建「经历 → JD → 简历 →（可选）投递任务」时间线（开发者视角）。
- [ ] 抽查默认日志无密钥与正文泄露。

## 4. 本机隐私与数据控制（P0 裁剪）

### 4.1 保留
- 导出本机业务数据（经历、JD、简历、Application、可选含对话/草稿）。
- 清除当前设备本地数据（语义准确：无云可回灌时需文案写明「仅本机」）。
- 隐私同意：记录政策版本与同意时间；重大变更需重新同意。

### 4.2 排除
- 删除 Coolto 云账号与云端全量删除。
- 「清除本机后云端仍在」类文案若产品无云，必须改掉以免误导。

### 4.3 验收
- [ ] 设置中有「导出本机数据」「清除本机数据」；文案与真实行为一致。
- [ ] 完整导出包数量/关系与 UI 可见资产对应。
- [ ] 清除本机后对话/草稿/任务/缓存按说明移除；无「假装删了云」的文案。
- [ ] 隐私同意含版本与时间；升级政策可触发重确认。

---

## 5. 跨平台安装与更新（P0 降级）

### 5.1 开源必达
- Windows / macOS 可从源码或发布物完成：安装/开发启动 → 配置 API → 主路径可用。
- 更新失败或中断不损坏本机业务数据（若有自动更新）；否则文档写明「开源版请自行管理版本」。

### 5.2 开源可选（非阻断）
- Authenticode / Apple 公证（商业门槛）；开源可文档化为 maintainer 可选步骤。

### 5.3 验收（必达）
- [ ] README 给出 Win/mac 开发启动与最小运行步骤。
- [ ] 配置用户自备 API 后可完成 §1 或 §2 至少一条主路径。
- [ ] 平台能力拒绝（如通知）时有降级说明，不伪造成功。

## 6. 职业画像（P1，本机）

用户可查看/编辑联系方式、目标岗位/城市/语言等宏观画像；对话变更需预览确认；空字段不臆造。

### 验收
- [ ] 设置页可编辑核心画像字段；可跳过仍能用基础功能。
- [ ] 对话提议改档案必须确认；临时指令不静默永久写入。
- [ ] 本机多用户/多工作区隔离（若支持多 profile）：无串数据。

---

## 7. 用户偏好学习（P1，本机）

显式偏好 + 「是否保存为偏好」建议；当前指令 > 显式偏好 > 建议；敏感信息不得入偏好库。

### 验收
- [ ] 可增删停用偏好；「以后都这样」先预览再保存。
- [ ] 冲突时本轮听当前消息；删除后新任务不再用。
- [ ] 抽查无密码/验证码/敏感身份。

---

## 8. 面试训练（P1，延后可选）

开源首期**不作为主路径阻断**。若实现：从本机 Application/Interview 发起文本模拟，事实须来自 Experience，禁止编造答词。

### 验收（仅当宣称支持时）
- [ ] 多轮追问模拟 + 可执行反馈 + 复盘绑定本机 Application。

---

## 9. 匹配分数可信表达（P1）

分数为相对参考非录用概率；信息不足降置信；报告记录模型/规则版本（本机配置名即可）。

### 验收
- [ ] UI 明确「非录用概率」。
- [ ] 高分/扣分项可回到 JD 要求与经历证据。
- [ ] 信息不足不输出假高精度。

---

## 10. 本机材料库（P1）

独立材料库、未归类区、多 Experience 关联、OCR 低置信须人工确认；原样投递文件默认不进事实抽取。

### 验收
- [ ] 可上传支持格式并见处理状态。
- [ ] 材料↔Experience 关联可查；删除前有影响说明。
- [ ] OCR 低置信标记；原样投递件未经授权不解析入库。

---

## 11. 浏览器站点记忆（P2，增强）

字段级自动/确认/仅手动策略；敏感类永不被记忆放开；结构变化旧规则失效。

### 验收（宣称支持时）
- [ ] 策略配置生效；仅手动字段不被自动写。
- [ ] 映射可复用；结构变则失效。
- [ ] 关联 JD/Application 仅建议、确认前不改 Tracker。

---

## 12. Agent 上下文与工具收敛（P1）

保持单一自然语言 Agent；按任务/阶段暴露最小工具集；目标切换与重启后过期句柄必须重取。

### 验收
- [ ] 简历任务不可见无关的最终投递/邮件发送等工具（以本仓实际工具清单为准做矩阵）。
- [ ] 阶段切换工具范围变化可说明/可测。
- [ ] 重启恢复要求重读过期页面/文件/工作区。
- [ ] 不新建第二套业务 Agent 或绕过 Proposal/审批。
